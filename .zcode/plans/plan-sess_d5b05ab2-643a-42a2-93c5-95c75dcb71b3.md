# Rencana Perbaikan Berkala (Berdasarkan qa-audit-report.md)

Strategi: Perbaikan bertahap (3 fase) tanpa merusak infrastruktur atau memutus koneksi aktif.

---

### Fase 1: Pembersihan Kode & Integritas Dasar (Risiko: Sangat Rendah)
Fokus perbaikan logika internal tanpa menyentuh kontrak API atau protokol eksternal.

1. **Dead Code Reply Handler (`worker/imap-poller.ts:108-118`)**
   - Hapus blok pengecekan kedua `msg.inReplyTo`.
   - Alasan: Unreachable code karena blok pertama sudah mengeksekusi `continue`.

2. **Atomic Delete Card (`src/app/api/cards/[id]/route.ts:138-140`)**
   - Bungkus penghapusan `ActivityLog`, `DraftMessage`, dan `Card` dalam `prisma.$transaction`.
   - Baca data kartu sebelum dihapus agar sinkronisasi arsip tetap memiliki referensi folder/UID.

3. **Validasi Tenant & Target Column (`src/app/api/cards/[id]/route.ts:51-57`)**
   - Tambah validasi kepemilikan tenant untuk `columnId` target pada endpoint `PUT`.
   - Cegah pemindahan kartu lintas-tenant (BOLA).

4. **Pengerasan TLS IMAP (`channels/email.ts:21`)**
   - Ganti `rejectUnauthorized: false` menjadi kondisional: `process.env.NODE_ENV === 'production' && process.env.IMAP_ALLOW_SELF_SIGNED !== 'true'`.
   - Alasan: Aman di produksi tanpa memutus server dev/self-signed.

---

### Fase 2: Akurasi Sinkronisasi Folder & Concurrency Worker (Risiko: Rendah-Sedang)
Fokus keandalan data email multi-folder dan proteksi duplikasi.

1. **Dinamisasi Folder IMAP (`src/app/api/cards/[id]/route.ts` & `channels/email.ts`)**
   - Gunakan `card.imapFolder || 'INBOX'` saat `mailboxOpen`, bukan string hardcoded `'INBOX'`.
   - Alasan: Email di shared folder tim (`Elite`, `Gold`, `Premiere`, `Nell`) sinkron status read/seen-nya.

2. **Mitigasi Race Condition Card Creation (`worker/imap-poller.ts:60-70`)**
   - Tangkap kode error Prisma `P2002` (unique constraint `messageId`) saat insert.
   - Fallback anggun: Abaikan duplikasi atau update `imapUid` tanpa melempar unhandled exception dan tanpa trigger antrean AI ganda.

---

### Fase 3: Dukungan OAuth2 & Stabilisasi Arsip (Risiko: Sedang)
Fokus penanganan akun Zoho OAuth2 dan fleksibilitas folder arsip.

1. **Integrasi OAuth2 Zoho pada IMAP Sync (`src/lib/imap-sync.ts`)**
   - Integrasikan `getValidZohoAccessToken` saat `config.authType === 'oauth2'` alih-alih langsung menolak jika `!config.imapPass`.
   - Sinkronisasi status read/archive berfungsi untuk pengguna Zoho OAuth.

2. **Verifikasi Folder Archive Fleksibel (`src/lib/imap-sync.ts` & `channels/email.ts`)**
   - Deteksi nama folder arsip (`Archive` / `Archives` / `Trash`) sebelum pemindahan.
   - Cegah unhandled crash jika mail server menggunakan penamaan folder non-Inggris.

3. **Non-Blocking IMAP Sync di API Route (`src/app/api/cards/[id]/route.ts`)**
   - Pastikan operasi IMAP status sync tidak memblokir respon HTTP pengguna (tetap asinkron atau dieksekusi via worker queue).
   - Alasan: Menghilangkan latensi 500ms - 3s pada UI Kanban saat toggle status kartu.
